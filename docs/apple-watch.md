# Murmur for Apple Watch

Oct 4 2026. Owner, on an Apple Watch SE 3: "Hey Siri, log an expense in
Murmur" on the wrist answered "I can't help you with that". Siri on the
watch only knows apps installed on the watch, and Murmur had none.

## Shape

```
watch: Siri phrase or tap + dictation
   -> PhoneLink.send (WatchConnectivity)
iPhone: WatchBridge (activated in didFinishLaunching, every launch)
   -> SiriCapture.file   <- the same function Siri on the iPhone uses
   -> capture queue -> JS drain -> app's own parser and save
   -> reply "Saved. $5.00 at Walmart." -> spoken / shown on the wrist
```

The watch is deliberately thin: no sign-in, no parser, no copy of the
categories. One save path for Siri on the phone and the wrist, so they cannot
disagree.

- **iPhone reachable:** `sendMessage`, which wakes Murmur in the background;
  the reply is what was really saved (9 s budget, same as Siri on the phone).
- **Not reachable:** `transferUserInfo`, delivered by the system when the
  watch and phone are back together; the watch says it will be filed then.

## Files

| Path | What |
|---|---|
| `apps/mobile/targets/watch/` | watchOS app (SwiftUI): screen, intents + App Shortcut phrases, PhoneLink, copy |
| `apps/mobile/native/ios/WatchBridge.swift` | iPhone side, WCSessionDelegate |
| `apps/mobile/native/ios/SiriLogExpense.swift` | `SiriCapture.file`, now shared by both |
| `apps/mobile/plugins/withMurmurIntents.js` | compiles WatchBridge into the app, activates it in AppDelegate |
| `apps/mobile/plugins/withWatchVersion.js` | watch version = iPhone version (App Store requires it; apple-targets hard-codes 1.0) |

Target generated by `@bacons/apple-targets` (`type: 'watch'`), bundle
`com.voiceexpense.app.watchkitapp`, watchOS 10+ (App Shortcuts). Siri phrases
are the same list as the iPhone's; keep them in sync.

## Verified

Compiles for watchOS and embeds in the iPhone app (`Murmur.app/Watch`),
versions match (1.0.1), iPhone app launches clean with the bridge active on
the iOS 27 simulator. No watchOS simulator runtime is installed on this Mac,
so the end-to-end test is on the owner's watch via TestFlight.

## App Store rule hit (build 75)

ITMS-90626 "Invalid Siri Support": App Intent descriptions cannot contain
"iPhone" (Apple rejects device names in Siri metadata). The watch intents
said "files it on your iPhone". Keep device names out of every
`IntentDescription`, `title` and parameter text; spoken dialogs at runtime
are fine.

## Siri on the watch filed late, with no banner (build 76, Oct 5 2026)

From the watch, the iPhone is reachable for live messaging only while the
watch app is in the foreground (Apple's WCSession rule). App Intents ran in
the background (`openAppWhenRun = false`), so `isReachable` was false, the
watch used `transferUserInfo`, and the iPhone filed the expense only when
Murmur was next opened: in-app toast, no banner. Tapping inside the watch app
worked because the app was in front.

Fix: the watch intents set `openAppWhenRun = true`, so the watch app comes
forward for the hand-off; `PhoneLink.send` waits up to 3 s for reachability
before falling back; the result is published to the watch screen. The first
Siri use also shows Apple's one-time "turn on Murmur shortcuts?" prompt,
which is expected.
