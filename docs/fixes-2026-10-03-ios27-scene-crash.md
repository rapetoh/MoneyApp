# iOS 27 killed Murmur at launch

Oct 3 2026. Owner: the app crashes on open; after delete + reinstall, iOS
showed `"Expense Tracker - Murmur" Crashed`.

## Cause

Five crash reports pulled straight off the owner's iPhone (paired to this
Mac, `xcrun devicectl device copy from --domain-type systemCrashLogs`), all
identical:

```
Murmur 1.0.1 build 67   iPhone OS 27.0.1 (24A446)
EXC_BREAKPOINT SIGTRAP
___UIApplicationEvaluateRuntimeIssueForNoSceneLifecycleAdoption_block_invoke
```

iOS 27 terminates, at launch and on purpose, any app that has not adopted
the UIScene lifecycle. Expo SDK 54's template (React Native 0.81) does not:
`AppDelegate` built a `UIWindow` in `didFinishLaunching` and `Info.plist` had
no `UIApplicationSceneManifest`. The phone updated to iOS 27 after Sep 30,
which is why Murmur worked until then and died on every launch after,
including a fresh reinstall. No JavaScript ran, which is why `app_events`
recorded no error and the server saw nothing.

It did not reproduce in the iOS 26.5 simulator, which does not enforce the
rule. It reproduced exactly on the iOS 27 simulator.

The Oct 2 diagnosis (an infinite splash from an uncaught keychain read,
docs/fixes-2026-10-02-launch-hang.md) was real and is still fixed, but it was
not what was killing this phone.

## Fix

`apps/mobile/plugins/withSceneLifecycle.js`, a config plugin, because `ios/`
is regenerated by prebuild on every EAS build:

1. `Info.plist` declares one window scene whose delegate is `SceneDelegate`.
2. `AppDelegate` still creates and binds the React Native factory (Expo's
   module system hooks in there) but no longer builds a window.
3. `SceneDelegate`, appended to `AppDelegate.swift` so it needs no Xcode
   project changes, builds the window from the scene and starts React Native.

The part that is easy to get wrong is deep links. Under scenes iOS stops
calling `application(_:open:options:)` and `application(_:continue:)`; URLs
go to the scene instead. Murmur needs them for sign-in, Shortcuts and Apple
Pay capture. So `SceneDelegate`:

- rebuilds `launchOptions` from the scene's connection options, because
  React Native's `Linking.getInitialURL()` reads the cold-start URL from
  `launchOptions[.url]` and nowhere else, and
- forwards every URL and user activity back through the existing
  `AppDelegate` methods, exactly as iOS did before scenes, so every Expo
  module and `RCTLinkingManager` hears what it always heard.

The plugin fails the prebuild if the template code it edits has moved. A
silent miss would ship an app that starts React Native twice or never.

## How this was run, so nobody has to ask the owner next time

See memory `project_ios_simulator_repro`. Simulator.app is not installed;
`xcodebuild` + `xcrun simctl` drive it headless, `idb` (installed for this,
`brew install facebook/fb/idb-companion`, `pip install --user fb-idb`) taps
and types, `simctl io screenshot` shows the screen. Device crash logs come
off a paired iPhone with `xcrun devicectl device copy from`.
