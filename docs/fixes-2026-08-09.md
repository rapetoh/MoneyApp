# Fixes — 2026-08-09: the eleven issues from the 2026-08-08 test session

**Scope:** every issue the owner reported from their 2026-08-08 production test
(screenshots in `remarks found on 08-08/`, verified issue-by-issue in
[audit-2026-08-08/00-YOUR-REPORTED-ISSUES.md](./audit-2026-08-08/00-YOUR-REPORTED-ISSUES.md)).
This document records what changed, where, and why — it does not replace the
full audit backlog in [audit-2026-08-08/10-FIX-PLAN.md](./audit-2026-08-08/10-FIX-PLAN.md),
which remains open for everything the owner did not personally hit.

## 1. Save button cut off in the Parsed Transaction sheet (voice + receipt + paycheck)

`VoiceConfirmModal`'s sheet caps itself at 72% of the screen, but the
`KeyboardAvoidingView` and `SafeAreaView` wrappers between the cap and the
content were unstyled (default `flexShrink: 0`), so tall content overflowed
past the physical screen bottom and the internal `ScrollView` never scrolled.

- `apps/mobile/src/components/VoiceConfirmModal.tsx` — `flexShrink: 1` on both
  wrappers, `overflow: 'hidden'` on the sheet. The body now scrolls when
  content exceeds the cap; the Save footer stays pinned above the home
  indicator. One component, so the fix covers all three entry flows at once.

## 2. "Scan Paycheck" spun the "Scan Receipt" button

One shared `scanLoading` boolean and a spinner ternary written only into the
receipt button.

- `apps/mobile/app/(tabs)/record.tsx` — `scanningType: 'receipt' | 'paycheck'
  | null` replaces the boolean; each button renders its own spinner; both
  disable (with a visible dimmed state) while either scan runs.

## 3. "PROCESSING" pill under the status-bar clock

The listening/processing takeover renders via early return outside the
screen's `SafeAreaView`, and had a fixed 8pt top padding.

- `apps/mobile/src/components/ListeningView.tsx` — the component now owns its
  safe area via `useSafeAreaInsets()` (`paddingTop: insets.top` on the root).

## 4. "Mark as recurring" promoted out of More options

Recurring is a forecast-altering, frequently used property; it now sits
directly under Category on the Manual tab.

- `apps/mobile/app/(tabs)/record.tsx` — `RecurringToggle` moved from the More
  options sheet into `quickFields`, using a new `variant="compact"`.
- `apps/mobile/src/components/RecurringToggle.tsx` — compact variant (tighter
  row, quickInput-matched surface). The parsed-transaction sheet keeps the
  default card variant.

## 5. Recurring rules were never created — architecture rebuilt

The defect: mobile saved the transaction offline-first, then inserted the rule
directly into Supabase pointing at a transaction the server didn't have yet →
foreign-key violation → `console.warn` → success UX with no rule. Frequency
choice lived only in React state and died with the failed insert.

**New architecture — the database owns rule creation:**

- `supabase/migrations/013_recurring_rule_ownership.sql` (**applied to
  production 2026-08-09**):
  - `transactions.recurring_frequency` column — the durable carrier of the
    user's cadence choice.
  - `trg_txn_recurring_link` (AFTER INSERT OR UPDATE OF is_recurring):
    find-or-create the active rule for (user, direction, merchant name),
    anchored so generators produce the *next* occurrence (never a duplicate of
    the flagged row), and write `recurring_rule_id` back onto the transaction.
    Atomic with the row write — the race is structurally gone.
  - `trg_txn_recurring_unflag`: unflagging the template deactivates its rule.
  - `idx_txn_recurring_dedup` narrowed to `source = 'recurring_generated'`
    (its real semantic; user-entered rows now legitimately carry
    `recurring_rule_id` too).
  - `idx_recurring_rules_active_name` makes find-or-create race-proof.
  - Backfill: the owner's Xtream $42/monthly and Charles Schwab $300/monthly
    rules were created and linked by this migration. An anchor guard advances
    stale `last_generated` values so backfilled old rules don't spray months
    of retroactive occurrences.
- Mobile (`record.tsx`, `transaction/edit.tsx`, `(onboarding)/income.tsx`,
  `useTransactions`, `transactionStore`, `localDb`, `recurringCatchUp`,
  shared `Transaction` type): `recurring_frequency` threaded end-to-end;
  client-side `createRule` calls deleted from all save paths; SQLite mirror
  column + narrowed mirror index; the local upsert's `ON CONFLICT` list now
  propagates `source`, `ai_confidence`, `is_recurring`, `recurring_rule_id`,
  `recurring_frequency` so server-assigned links survive sync echoes.
- `useRecurringRules.computeUpcomingRecurring` now counts only `debit` rules —
  income rules must never inflate "upcoming spend".

Any writer on any platform (mobile, web, desktop) that sets
`is_recurring = true` now gets a rule, by construction.

## 6. Web SOURCE column showed "Recurring" for a manual transaction

`classifySource` put the `is_recurring` flag ahead of the real source.
Recurrence is not a source.

- `apps/web/src/app/dashboard/transactions/page.tsx` — SOURCE derives strictly
  from `transactions.source` (Voice / Typed / Scan / Apple Pay / Auto, where
  Auto = engine-generated occurrences, the one genuinely non-human source).
  The Recurring filter chip and the subtitle's recurring count key off the
  flag. The recurring icon beside the merchant name stays. `scan` rows no
  longer masquerade as "Typed".

## 7. Calendar showed July when August was selected (and the empty grid, and Aug 1 under FRI)

The server component built month anchors as UTC `Date` instants; client lenses
re-read them with browser-local getters — one month/day off for every user
west of UTC, i.e. every US user.

- `apps/web/src/components/lenses/types.ts` — `LensProps` now carries
  `anchorYear` / `anchorMonth` as timezone-free numbers, with the rule
  documented: lenses must never call date getters on the instant props.
- `apps/web/src/app/dashboard/page.tsx` — passes the numbers; title uses them.
- `Calendar.tsx` — grid identity, weekday offset, day panel, and bucketing all
  from the anchor numbers; day membership judged in the viewer's timezone.
- `Cashflow.tsx`, `Matrix.tsx`, `MindMap.tsx` — same class of read fixed
  (Matrix's `buildMonths` now takes numbers; MindMap's year label).

## 8. Budgets page: unlabeled "$92" in the no-budget ring

The ring center's big number rendered unconditionally while its explanatory
lines were budget-gated — a real spend figure stripped of its meaning.

- `apps/web/src/app/dashboard/budgets/page.tsx` — no-budget state now renders
  the figure with an explicit "spent this month" label; the has-budget state
  is unchanged.

## 9. Forecast "$1,519 projected for August" from three transactions

The number was `(spend ÷ days elapsed) × days in month` — a raw run-rate
presented as a forecast, with the chart's "Actual" series silently overwritten
by the projection and the future months fabricated from it.

- `apps/web/src/app/dashboard/insights/page.tsx`:
  - Headline is now the actual month-to-date, with the projection demoted to a
    labeled method: "at this pace: $X by Aug 31" (suppressed before day 3 of a
    month or with zero spend).
  - The Actual series plots actuals only. The dashed forecast carries the
    current-month pace point, and future months only when ≥ 2 complete months
    of real spend exist — otherwise nothing is drawn rather than invented.
  - "Heaviest day" pattern: a true average (weekday total ÷ distinct such
    weekdays), labeled "per Saturday", and only claimed after ≥ 4 weeks of
    history.
  - The "Based on N transactions across the last 6 months" subtitle now counts
    only transactions inside that window.

## 10. AI: "investing $300 at Charles Schwab" classified as income; "S&P 500" discarded

The prompt's entire direction rule was eleven words, and the recurring rule
primed investment vocabulary as income. `note` did not exist anywhere in the
parse contract.

- `packages/ai/src/prompt.ts` — direction defined by money flow with an
  explicit investing example (money out to brokerage/savings = debit; money
  received = credit); recurring rule declared independent of direction; `note`
  extraction added to the voice prompt and both scan prompts (receipt line
  items, paycheck pay period).
- `packages/shared/src/types/ai.ts` — `ParsedExpense.note`.
- `packages/ai/src/parser.ts` / `localParser.ts` / notification listener /
  shortcut injection — `note` mapped at every construction site.
- `apps/mobile/src/components/VoiceConfirmModal.tsx` — Note field pre-seeded
  from the parse result; flows into the saved transaction as before.

**Deliberately unchanged:** `raw_transcript` still never syncs to the server —
that is the shipped privacy promise ("voice processed on-device", migration
009). Reversing it is a product decision, not a bug fix.

## Verification

- `tsc --noEmit` clean for `apps/mobile` and `apps/web`; `next build` passes.
- Migration applied to production and confirmed by querying `recurring_rules`:
  Xtream and Charles Schwab rules exist, active, linked from their
  transactions.
- Each fix adversarially reviewed against its original symptom by an
  independent 10-agent verification pass before commit. 9/10 confirmed
  outright; every substantive finding from the pass was then fixed:
  - **Small-screen fit** (flagged REGRESSION_RISK): the promoted recurring
    toggle could push the keypad/CTA under the tab bar on SE-class iPhones.
    The Manual tab's top cluster is now a shrinkable ScrollView — fields
    scroll internally on short screens; the keypad and Add CTA never move.
  - `supabase/migrations/014_recurring_trigger_idempotency.sql` (**applied to
    production**): the trigger now relinks via `template_txn_id` first, so a
    stale offline echo that clears the link can never mint a duplicate rule
    for NULL-merchant transactions.
  - Accepting a detected pattern whose merchant already has an active rule
    (e.g. a price change) now **merges into the existing rule** instead of
    dying silently on the unique index — web `acceptCandidate` and mobile
    `createRule` both.
  - Edit screen prefills frequency from the transaction's own
    `recurring_frequency` (offline-safe), falling back to the linked rule.
  - `parse-expense` route `max_tokens` 200 → 320 so the new `note` field
    cannot truncate the JSON payload.

Known accepted nits (documented, not fixed here): iOS sheet top-shadow is
clipped by the sheet's `overflow: hidden` (kept — it also clips scrolled
content at the rounded corners); engine-generated rows count as "typed" in the
transactions subtitle until a dedicated bucket is warranted; the
KeyboardAvoidingView coordinate-space under-padding inside modals is a
pre-existing app-wide defect tracked as audit F37.
